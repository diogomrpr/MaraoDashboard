## Use in Home Assistant

In Home Assistant, choose **Edit dashboard → Add card → Manual**, then paste the YAML below. Replace fictional entity IDs with your own. You can also find the card in Home Assistant’s card picker and use its native editor.

```yaml
type: custom:marao-header-card
entity_id: weather.home
variables:
  person_entity: person.alex
  air_quality_sensor: sensor.air_quality
```

Compatible entity domains: `weather`.

A header combines current weather with the explicitly selected person and optional air quality reading. Missing optional entities do not become invented measurements.

## Settings

The table lists the shared catalog fields and this card’s structured options. **Not set** means the example does not impose a value; Home Assistant and Marao use the entity’s capabilities and the card’s normal behavior. Structured values remain editable as YAML.

| YAML path | Setting | Value type | Catalog default | Behavior |
| --- | --- | --- | --- | --- |
| `entity_id` | Entity | entity | Not set | A weather entity from your Home Assistant. Searchable suggestions are available. |
| `name` | Name | text | Not set | Optional display name; otherwise use the entity’s friendly name. |
| `icon` | Icon | icon | Not set | Optional icon name such as mdi:lightbulb-outline. Searchable suggestions are available. |
| `variables.person_entity` | Person | entity | Not set | Person for this card. Searchable suggestions are available. |
| `variables.air_quality_sensor` | Air quality | entity | Not set | Air quality for this card. Searchable suggestions are available. |
| `variables.activity_entities` | Related activity entities | json | Not set | Related activity entities for this card. Searchable suggestions are available. |

## Behavior examples

Select **Open playground**, then choose a scenario to inspect its configuration and reported device state. Similar numeric or color values do not need separate examples.

| Scenario | What it demonstrates |
| --- | --- |
| Default | Try the configured card with fictional devices. |
| Person away | The person’s reported place changes independently of weather. |
| Weather only | Remove optional person and air-quality readings. |
| Loading state | Wait for Home Assistant state before showing controls. |
| Unknown state | The entity exists but has no known state. Controls remain neutral and disabled. |
| Unavailable | The entity is unavailable. No device action is dispatched. |
| Missing entity | A removed entity produces an explicit neutral missing-state result. |
| Disconnected | Controls refuse actions when Home Assistant is disconnected. |

## Layout and shared behavior

Home Assistant owns card sizing, sections and visibility. Marao controls retain their touch targets and capability checks. Unknown, unavailable or disconnected entities use neutral presentation and disable unsafe actions. See [layouts and popups](../../features/layout/) and [shared interactions](../../features/theme/).
