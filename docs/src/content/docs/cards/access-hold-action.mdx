## Use in Home Assistant

In Home Assistant, choose **Edit dashboard → Add card → Manual**, then paste the YAML below. Replace fictional entity IDs with your own. You can also find the card in Home Assistant’s card picker and use its native editor.

```yaml
type: custom:marao-access-hold-action-card
entity_id: button.entry
variables:
  access_mode: hold
```

Compatible entity domains: `button`, `switch`, `input_boolean`, `alarm_control_panel`, `lock`.

A risky action requires the complete security hold. Choose its entity and optional native service in the card editor. A lock can only use lock.lock here; unlocking requires Access opener.

## Settings

The table lists the shared catalog fields and this card’s structured options. **Not set** means the example does not impose a value; Home Assistant and Marao use the entity’s capabilities and the card’s normal behavior. Structured values remain editable as YAML.

| YAML path | Setting | Value type | Catalog default | Behavior |
| --- | --- | --- | --- | --- |
| `entity_id` | Entity | entity | Not set | A button, switch, input_boolean, alarm_control_panel, lock entity from your Home Assistant. Searchable suggestions are available. |
| `name` | Name | text | Not set | Optional display name; otherwise use the entity’s friendly name. |
| `icon` | Icon | icon | Not set | Optional icon name such as mdi:lightbulb-outline. Searchable suggestions are available. |
| `show_name` | Show name | boolean | Not set | Optional native card appearance setting. Normal availability warnings remain visible. |
| `show_icon` | Show icon | boolean | Not set | Optional native card appearance setting. Normal availability warnings remain visible. |
| `show_state` | Show state | boolean | Not set | Optional native card appearance setting. Normal availability warnings remain visible. |
| `show_label` | Show label | boolean | Not set | Optional native card appearance setting. Normal availability warnings remain visible. |
| `variables.custom_label` | Custom state label | text | Not set | Custom state label for this card. |
| `variables.md_label_prefix` | State label prefix | text | Not set | State label prefix for this card. |
| `variables.card_color` | Card color | color | Not set | Optional card background color. |
| `variables.active_color` | Active color | color | Not set | Active color for this card. |
| `variables.access_mode` | Access behavior | select | `auto` | Access behavior for this card. Choices: `auto`, `popup`, `slide`, `close`, `hold`. |
| `variables.action_color` | Action color | color | Not set | Optional action background color; does not change the action’s safety rules. |
| `variables.action_label` | Action label | text | Not set | Optional visible action label. |
| `variables.action_label_key` | Action translation key | text | Not set | Optional Marao localization key for the action label. Searchable suggestions are available. |
| `variables.activity_entities` | Related activity entities | json | Not set | Related activity entities for this card. Searchable suggestions are available. |
| `variables.action_service` | Action service | text | Not set | Action service for this card. Searchable suggestions are available. |

## Behavior examples

Select **Open playground**, then choose a scenario to inspect its configuration and reported device state. Similar numeric or color values do not need separate examples.

| Scenario | What it demonstrates |
| --- | --- |
| Default | Try the configured card with fictional devices. |
| Switch action | A switch action keeps the security hold. |
| Held lock button | Require the hold before locking. Unlocking remains a separate slider. |
| Loading state | Wait for Home Assistant state before showing controls. |
| Unknown state | The entity exists but has no known state. Controls remain neutral and disabled. |
| Unavailable | The entity is unavailable. No device action is dispatched. |
| Missing entity | A removed entity produces an explicit neutral missing-state result. |
| Disconnected | Controls refuse actions when Home Assistant is disconnected. |

## Layout and shared behavior

Home Assistant owns card sizing, sections and visibility. Marao controls retain their touch targets and capability checks. Unknown, unavailable or disconnected entities use neutral presentation and disable unsafe actions. See [layouts and popups](../../features/layout/) and [shared interactions](../../features/theme/).
