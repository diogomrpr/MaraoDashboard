## Use in Home Assistant

In Home Assistant, choose **Edit dashboard → Add card → Manual**, then paste the YAML below. Replace fictional entity IDs with your own. You can also find the card in Home Assistant’s card picker and use its native editor.

```yaml
type: custom:marao-media-card
entity_id: media_player.living_room
```

Compatible entity domains: `media_player`.

Popup is the default. Inline places the same owned media controls on the dashboard.

Playback, seek, volume, sources and remote controls depend on the entity’s capabilities; selection lists use the reported sources. Built-in media and Apple TV remote buttons use a single tap, including directions and Select. They show brief press feedback without a hold countdown or long command.

## Plex library

Open this card's **Apple TV options → Plex setup** to enable the owned Plex Watch section. It uses this card's television automatically. Choose **Plex** or **Rivulet** as the **Playback app** here rather than creating another TV card. With several configured Apple TV cards, the library's Marao dropdown lets you switch between their named mappings. Opening from a different Apple TV card selects that card's TV again.

Add Home Assistant's **Plex Media Server** integration first. Use the same single Plex server/profile in HA and the selected Apple TV app. For **Plex** playback, open Plex on the TV once so HA can discover its media-player client. Select that **Plex client**, the integration's **Scan-clients button**, and the exact **Plex app source** supported by this card's TV. **Choose library folders** browses HA's returned servers; choose **Use this server**. If Continue Watching discovery is ambiguous, open the appropriate recommendation folder and select **Use for Continue Watching**. Setup and browsing do not wake a television or change server settings.

The library home has exactly three open shelves: **Continue Watching**, **Movies**, and **TV Series**, in that order. Each shelf scrolls independently with native horizontal touch scrolling and visible Previous/Next controls. Larger portrait covers (about 160 × 240px) have wrapping titles below them; **Load more** extends that rail without resetting the others. Movie/show shelves merge first-level contents of matching libraries in returned order, using media metadata rather than library names; identical references are deduplicated, while distinct editions remain. Unclassified libraries are checked by their direct children, and failures stay readable alongside usable shelves. No seasons or per-title metadata are fetched until browsing. Tap an episode or movie to resume/play; show and season tiles open their contents. Opening a series from the dashboard keeps the home shelves in place; details inside a media sheet reuse that sheet. Back restores shelf positions and retains the selected TV. **Browse library** offers the library tree and Recently Added when supplied by Plex. Missing recommendations and empty folders have separate explanations; unavailable artwork uses a neutral poster. Only metadata supplied by HA is shown, so the card does not invent watch-progress percentages. **Refresh** and **Retry** are explicit actions; the library does not poll in the background.

One title tap gives strong haptic feedback and wakes an off TV. **Plex** playback opens Plex and waits up to 30 seconds for its mapped Plex client before sending one playback request. **Rivulet** playback sends a movie/episode link directly to the selected Apple TV; Rivulet opens and resumes at its saved position. It requires Rivulet with content-link support (confirmed in v1.2.0-122), already signed into the same selected Plex server/profile. The link does not switch servers/profiles. No Plex app launch or client scan is needed for Rivulet playback. Already-satisfied steps are skipped. Changing TV, closing the browser, editing the card or losing the connection cancels subsequent launch steps. Requests already sent to HA cannot be recalled. A readable failure allows an explicit retry; the existing Now playing display remains based on HA reports.

The Watch section is available in automatic **Popup** and **On dashboard** media presentations. In a popup, library navigation stays in that sheet; inline cards open Marao's normal library sheet. Explicit custom popup layouts remain independently authored: switch deliberately to automatic details before enabling this section. Ordinary app shortcuts keep their existing source-launch action.

For **Rivulet**, choose your configured server using **Choose library folders → Use this server**. HA 2026.10 exposes Plex browsing through a registered media-player entity, including inactive session entities. Play something once in Rivulet so HA can discover a session; then use **Retry** in the card. The card automatically finds an enabled Plex entity for that server, or you can choose a **Plex browse entity (optional)**. That entity supplies library/Continue Watching metadata and never receives Rivulet playback commands. Until discovery, the card shows a setup explanation and retains your real server selection. The official Plex app is not required for Rivulet playback.

The optional configuration lives under `apple_tv.plex`; use the visual folder picker for the returned content references:

```yaml
type: custom:marao-media-card
entity_id: media_player.example_apple_tv
apple_tv:
  remote_entity: remote.example_apple_tv
  plex:
    client_entity: media_player.example_plex_client
    scan_clients_entity: button.example_plex_scan_clients
    app_source: Plex
    library_root:
      media_content_type: server
      media_content_id: plex://example-server/server
```

For Rivulet, replace the playback-only client/scan/source fields with `playback_app: rivulet` and keep the selected server reference:

```yaml
apple_tv:
  remote_entity: remote.example_apple_tv
  plex:
    playback_app: rivulet
    # Optional: any registered Plex entity belonging to this server.
    # browse_entity: media_player.example_plex_session
    library_root:
      media_content_type: server
      media_content_id: plex://example-server/server
```

These IDs are fictional. Missing `playback_app` retains Plex playback. Missing `plex` or `plex: false` keeps the section disabled; an optional `continue_watching` object uses the same `media_content_type`/`media_content_id` shape. No Plex password or token belongs in this configuration. Credentials and poster authentication stay with HA through its Plex image proxy. This feature does not switch Plex profiles, manage the server/library, edit watch history, manage queues or stream via AirPlay.
## Settings

The table lists the shared catalog fields and this card’s structured options. **Not set** means the example does not impose a value; Home Assistant and Marao use the entity’s capabilities and the card’s normal behavior. Structured values remain editable as YAML.

| YAML path | Setting | Value type | Catalog default | Behavior |
| --- | --- | --- | --- | --- |
| `entity_id` | Entity | entity | Not set | A media_player entity from your Home Assistant. Searchable suggestions are available. |
| `name` | Name | text | Not set | Optional display name; otherwise use the entity’s friendly name. |
| `icon` | Icon | icon | Not set | Optional icon name such as mdi:lightbulb-outline. Searchable suggestions are available. |
| `show_name` | Show name | boolean | Not set | Optional native card appearance setting. Normal availability warnings remain visible. |
| `show_icon` | Show icon | boolean | Not set | Optional native card appearance setting. Normal availability warnings remain visible. |
| `show_state` | Show state | boolean | Not set | Optional native card appearance setting. Normal availability warnings remain visible. |
| `show_label` | Show label | boolean | Not set | Optional native card appearance setting. Normal availability warnings remain visible. |
| `tap_action` | tap action | json | Not set | Configure through Home Assistant’s native action selector. Role and access safety checks still apply. |
| `hold_action` | hold action | json | Not set | Configure through Home Assistant’s native action selector. Role and access safety checks still apply. |
| `double_tap_action` | double tap action | json | Not set | Configure through Home Assistant’s native action selector. Role and access safety checks still apply. |
| `variables.custom_label` | Custom state label | text | Not set | Custom state label for this card. |
| `variables.md_label_prefix` | State label prefix | text | Not set | State label prefix for this card. |
| `variables.card_color` | Card color | color | Not set | Optional card background color. |
| `variables.active_color` | Active color | color | Not set | Active color for this card. |
| `variables.media_display` | Display | select | Not set | Popup or On dashboard. Missing keeps Popup. Choices: `popup`, `inline`. |
| `variables.md_show_background_art` | Background artwork | boolean | `true` | Background artwork for this card. |
| `variables.md_background_color` | Background color | color | Not set | Background color for this card. |
| `variables.popup_hash` | Popup hash | text | Not set | Optional link to an existing external popup hash. Omit it to use this card’s automatic details. |
| `popup_view` | Custom popup view | text | Not set | Optional existing view path used for a Home Assistant managed popup layout. Omit for automatic details. Searchable suggestions are available. |
| `apple_tv` | Remote and app shortcuts | json | Not set | Optional remote_entity, volume_remote_entity and app shortcut configuration. |

## Behavior examples

Select **Open playground**, then choose a scenario to inspect its configuration and reported device state. Similar numeric or color values do not need separate examples.

| Scenario | What it demonstrates |
| --- | --- |
| Default | Try the configured card with fictional devices. |
| Inline controls | Show media controls directly on the page. |
| Paused | Play resumes the fictional media session. |
| Idle | An idle player does not display invented media metadata. |
| Plain background | Hide background artwork. |
| Remote and shortcuts | Use configured remote commands and named application sources. |
| Loading state | Wait for Home Assistant state before showing controls. |
| Unknown state | The entity exists but has no known state. Controls remain neutral and disabled. |
| Unavailable | The entity is unavailable. No device action is dispatched. |
| Missing entity | A removed entity produces an explicit neutral missing-state result. |
| Disconnected | Controls refuse actions when Home Assistant is disconnected. |

## Layout and shared behavior

Home Assistant owns card sizing, sections and visibility. Marao controls retain their touch targets and capability checks. Unknown, unavailable or disconnected entities use neutral presentation and disable unsafe actions. See [layouts and popups](../../features/layout/) and [shared interactions](../../features/theme/).
