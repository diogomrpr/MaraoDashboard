## Use in Home Assistant

In Home Assistant, choose **Edit dashboard → Add card → Manual**, then paste the YAML below. Replace fictional entity IDs with your own. You can also find the card in Home Assistant’s card picker and use its native editor.

```yaml
type: custom:marao-entity-group-card
name: Lights
id: lights
entity_type: light
entities:
  - light.living_room
  - light.kitchen
  - light.desk
popup_filter: active
summary_sections:
  - id: ground-floor
    name: Ground floor
    entities:
      - light.living_room
      - light.kitchen
```

The summary reflects the selected members, including unavailable members and the worst battery where applicable.

Section actions operate on eligible members once per service batch. Buttons keep their action labels without a repeated eligibility sentence; reported service errors remain visible. Access opening remains an individual deliberate slide, and unsafe or unsupported targets are excluded. Use **Edit popup** in the saved card's native editor to edit its layout.

Managed popup layouts keep type, member selection and filter in this parent
editor. Local placement, labels and custom cards remain in the Sections view.
Switching group type retains the previous type's managed layout and selection
for returning later. Child controls offer **Make custom** for independent
behavior; see [popup ownership](../../features/popups/).

## Settings

The table lists the shared catalog fields and this card’s structured options. **Not set** means the example does not impose a value; Home Assistant and Marao use the entity’s capabilities and the card’s normal behavior. Structured values remain editable as YAML.

| YAML path | Setting | Value type | Catalog default | Behavior |
| --- | --- | --- | --- | --- |
| `name` | Name | text | Not set | Optional display name; otherwise use the entity’s friendly name. |
| `icon` | Icon | icon | Not set | Optional icon name such as mdi:lightbulb-outline. Searchable suggestions are available. |
| `popup_view` | Custom popup view | text | Not set | Optional existing view path used for a Home Assistant managed popup layout. Omit for automatic details. Searchable suggestions are available. |
| `id` | Stable group ID | text | Not set | Unique local identifier for this group. |
| `entity_type` | Group type | select | Not set | Supported summary family. Choices: `light`, `cover`, `climate`, `battery`. |
| `entities` | Members | json | Not set | An ordered explicit list of compatible entity IDs or descriptors. Searchable suggestions are available. |
| `summary_sections` | Summary sections | json | Not set | Named sections with unique IDs and non-overlapping member lists. Unassigned members appear under Other. |
| `popup_filter` | Popup filter | select | Not set | Choose active members or all members. Choices: `active`, `all`. |

## Layout and shared behavior

Home Assistant owns card sizing, sections and visibility. Marao controls retain their touch targets and capability checks. Unknown, unavailable or disconnected entities use neutral presentation and disable unsafe actions. See [layouts and popups](../../features/layout/) and [shared interactions](../../features/theme/).
