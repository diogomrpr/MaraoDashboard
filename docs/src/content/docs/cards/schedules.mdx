## Use in Home Assistant

In Home Assistant, choose **Edit dashboard → Add card → Manual**, then paste the YAML below. Replace fictional entity IDs with your own. You can also find the card in Home Assistant’s card picker and use its native editor.

```yaml
type: custom:marao-schedules-card
name: Garden schedules
group_id: garden
targets:
  - switch.garden
  - valve.garden
```

An administrator sets up the collection and acknowledges dedicated devices. Home Assistant owns the automations and stop timers; the browser does not need to stay open.

Seasonal groups select which future starts are allowed. Pausing or switching groups does not cancel accepted timed runs.

Timers use weekdays, a local start time and an explicit Turn on or Turn off action. New timers use the card’s configured devices and the section they belong to. Existing duration-based records retain their saved behavior.

Structural external edits and ambiguous ownership are read-only until reconciled. Keep native Home Assistant backups before resource changes.

## Settings

The table lists the shared catalog fields and this card’s structured options. **Not set** means the example does not impose a value; Home Assistant and Marao use the entity’s capabilities and the card’s normal behavior. Structured values remain editable as YAML.

| YAML path | Setting | Value type | Catalog default | Behavior |
| --- | --- | --- | --- | --- |
| `name` | Name | text | Not set | Optional display name; otherwise use the entity’s friendly name. |
| `icon` | Icon | icon | Not set | Optional icon name such as mdi:lightbulb-outline. Searchable suggestions are available. |
| `group_id` | Collection ID | text | Not set | Stable collection identity shared by cards referring to the same schedule records. |
| `targets` | Dedicated devices | json | Not set | Explicit switch, valve or input_boolean entity IDs. Searchable suggestions are available. |

## Website preview limits

All automation/helper records and device actions are in memory. The demonstration does not create schedules in Home Assistant or simulate elapsed-day execution.

## Layout and shared behavior

Home Assistant owns card sizing, sections and visibility. Marao controls retain their touch targets and capability checks. Unknown, unavailable or disconnected entities use neutral presentation and disable unsafe actions. See [layouts and popups](../../features/layout/) and [shared interactions](../../features/theme/).

Groups appear as collapsible sections with only one open at a time. The active group opens initially; its switch activates or pauses it. Tap a timer to edit or delete it in a popup. Use the plus buttons below timers or groups to add a new item.

Timer switches are beside their list rows. The timer popup saves completed edits automatically and keeps errors visible; closing flushes pending edits. Use the top-right close button or the red trash action. Configuration reloads and automation state changes refresh automatically. The card has no manual Refresh, Delete collection, device-status list, duration editor or per-timer group/device picker.

Group sections expose a red delete icon instead of a management dialog. Timer rows open settings without a redundant arrow. Weekdays use a themed multi-select dropdown with checkmarks and a selected-day summary.
