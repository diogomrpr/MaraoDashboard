# Design
Use CameraPlayback's existing timeout, progress monitor, autoplay/fullscreen, eligibility and cleanup lifecycle. Native advancement wins without provider discovery. After failure, resolve Frigate identity from that selected camera's documented client_id/camera_name attributes; never infer another camera from entity names. Discover the exact stream through the authenticated integration go2rtc API. Use its generic WebSocket proxy or the older authenticated MSE route when the generic API is absent. Sign the precise request through HA; never use direct NVR URLs, configuration credentials, external players or another camera's overrides.

Implement the small go2rtc MSE protocol with browser-native MediaSource/ManagedMediaSource, codec negotiation, bounded append buffering and eviction. No third-party card/library. Keep each candidate within the existing playback wait, require actual media advancement, and release the native signaling/player or MSE socket/source buffer/object URL before advancing. Generation checks and AbortController invalidate discovery/signing on target change, removal, navigation, preview or disconnection. Retry explicitly starts a fresh native-first attempt. Do not repeatedly restart exhausted paths on state updates.

No persisted changes or historical fixture rewrites. Native and provider paths share the original camera entity and event popup. Use focused unit regressions for native success, native rejection/stall with provider success, exhaustion, authorization/camera isolation and cleanup. Browser validation only on safe disposable fixtures where practical; Safari/real-camera results must be reported honestly. Do not run retired slow-link/HLS/native-handoff campaigns.

Protocol references checked 2026-11-22: frigate-hass-integration master camera.py (identity) and views.py (authenticated go2rtc/MSE proxies); go2rtc www/video-rtc.js (MSE handshake and Safari ManagedMediaSource). These are protocols, not imported/copied third-party runtime code.
